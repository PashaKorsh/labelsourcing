# Спецификация Backend API (v1.1)

**Проект:** Сервис разметки данных  
**Base URL:** `/api/v1`

---

## 1. Auth (Авторизация)

| Метод | Путь | Описание |
|:---|:---|:---|
| **POST** | `/auth/login` | Авторизация по паролю (OAuth2). Принимает `form-data`. |
| **GET** | `/auth/yandex/login` | Инициация входа через Яндекс OAuth. |
| **GET** | `/auth/yandex/callback` | Callback-эндпоинт для обмена кода на токен и выдачи JWT. |

### Детали реализации Auth:
* **`/login`**: Использует `OAuth2PasswordRequestForm`. Возвращает JWT токен.
* **`/yandex/login`**: Принимает `success_url` и `error_url`. Редиректит на Яндекс. Состояние (state) используется для передачи путей возврата.
* **`/yandex/callback`**: Основной узел интеграции. Создает пользователя в БД при первом входе, выпускает внутренний JWT и делает финальный редирект.

## 2. Users (Пользователи)

| Метод | Путь | Доступ | Описание |
|:---|:---|:---|:---|
| **GET** | `/users/me` | Auth | Профиль текущего пользователя (имя, аватар, роли, теги). |
| **GET** | `/users/` | Admin | Список всех пользователей с пагинацией. |
| **PATCH** | `/users/{id}` | Admin | Изменение ролей и тегов пользователя. |

**Замечания и улучшения:**
* В `GET /users/` добавлена обязательная пагинация (`limit/offset`).
* Роли и теги теперь возвращаются сразу в `/me`, чтобы фронтенд мог строить UI без лишних запросов.

## 3. Datasets (Датасеты)

| Метод | Путь | Доступ | Описание |
|:---|:---|:---|:---|
| **GET** | `/datasets/` | Auth | Список доступных датасетов с фильтрами. |
| **POST** | `/datasets/` | Admin | Создание нового датасета. |
| **GET** | `/datasets/{id}` | Auth | Детальная информация и полные счетчики. |
| **PATCH** | `/datasets/{id}` | Admin | Выборочное редактирование параметров датасета. |

**Замечания и улучшения:**
* **Фильтрация в GET:** Поддержка Query-параметров: `status` (new, started, done), `search` (по имени), `owner_id`.
* **Оптимизация:** Список возвращает только базовые счетчики (из кеша), детальные — только в GET по конкретному ID.

## 4. Tasks (Задачи)

| Метод | Путь | Доступ | Описание |
|:---|:---|:---|:---|
| **GET** | `/datasets/{id}/next` | Auth | Выдача следующей задачи (с механизмом блокировки). |
| **POST** | `/tasks` | Auth | Загрузка одной задачи (через внешний URL). |
| **POST** | `/tasks/batch` | Admin | Массовый импорт задач (список ссылок/путей). |
| **GET** | `/datasets/{id}/tasks` | Admin | Список всех задач датасета (пагинация обязательна). |

**Замечания и улучшения:**
* **Механизм Lock:** При вызове `/next` задача резервируется за пользователем на 15-30 минут. Это предотвращает одновременную разметку одного объекта разными людьми.
* Эндпоинт `/tasks/dataset/{id}` (из старой версии) ограничен для обычных пользователей в целях безопасности и заменен на логику `/next`.

## 5. Labels (Разметка)

| Метод | Путь | Доступ | Описание |
|:---|:---|:---|:---|
| **PUT** | `/tasks/{id}/labels` | Auth | Сохранение или обновление разметки задачи. |
| **PATCH** | `/labels/{id}/status` | Mod/Admin | Изменение статуса (Verified/Rejected). |

**Замечания и улучшения:**
* **Идемпотентность:** Метод заменен на `PUT`. При повторном сохранении разметки для той же задачи данные просто обновляются.
* Статус разметки теперь управляет жизненным циклом задачи (если `Rejected` — задача снова попадает в пул доступных).

## 6. Sources & Tags (Системное)

| Метод | Путь | Доступ | Описание |
|:---|:---|:---|:---|
| **GET** | `/sources` | Admin | Список настроенных источников (алиасов путей). |
| **GET** | `/tags/` | Auth | Список доступных тегов (пагинация). |
| **POST** | `/tags/` | Admin | Создание тега (name, color). |

**Замечания и улучшения:**
* **Безопасность Sources:** Реализована схема `{uuid}/path`. UUID — это алиас (например, `S3-Bucket-1` или `Local-NAS`), настроенный на бэкенде. Реальные пути скрыты.
* **Валидация путей:** Бэкенд должен проверять отсутствие `../` в пути, чтобы исключить доступ к системным файлам.

---

## Общие требования и безопасность

1. **Валидация данных:** Все входящие JSON-объекты должны проходить строгую валидацию (типы данных, обязательные поля, границы координат).
2. **Пагинация:** Все эндпоинты, возвращающие списки (`GET`), должны поддерживать параметры `limit` и `offset`.
3. **Версионирование:** Все запросы начинаются с `/api/v1/`.
4. **Статусы ответов:**
   * `200 OK` / `201 Created` — успех.
   * `403 Forbidden` — если разметчик пытается редактировать чужую разметку или зайти в админку.
   * `409 Conflict` — если задача уже заблокирована другим пользователем.
   * `422 Unprocessable Entity` — ошибка валидации данных.
