# Экспорт разметки (формат, близкий к COCO)

Эндпоинт: `GET /api/v1/datasets/{dataset_id}/export/coco`
Доступ: администратор или владелец датасета.

Возвращает разметку датасета в JSON, структурно близком к
[COCO](https://roboflow.com/formats/coco-json), но с одним важным отличием в координатах
(см. раздел «Почему координаты не в пикселях»).

---

## Что попадает в выгрузку

- Берутся `done`-разметки только annotation-задач.
- Если у датасета включена валидация (`requires_validation = true`) — только разметки,
  прошедшие валидацию (`is_validated = true`). Без валидации — все завершённые разметки.
- Каждая фигура (bbox или полигон) становится отдельным объектом в `annotations`.

---

## Структура ответа

```jsonc
{
  "info": {
    "name": "<title датасета>",
    "description": "<описание>",
    "date_created": "<created_at в ISO>",
    "requires_validation": true
  },
  "images": [
    { "id": 0, "file_name": "<task.url>", "height": 1, "width": 1 }
  ],
  "annotations": [
    {
      "id": 0,
      "image_id": 0,
      "category_id": 2,
      "bbox": [x, y, width, height],
      "area": 0.0123,
      "segmentation": [],
      "iscrowd": 0
    }
  ],
  "categories": [
    { "id": 0, "name": "<label метки>" }
  ]
}
```

### `categories`

Строятся из `settings.annotation_labels` датасета. `category_id` — это индекс метки в списке
`annotation_labels` (0, 1, 2, ...). Если у фигуры не нашлось совпадения по метке — `category_id = 0`.

### `images`

Один элемент на задачу, у которой есть выгружаемая разметка. `file_name` — это `task.url`
(для URL-датасета это ссылка, для utility-датасета — относительный путь файла внутри папки).

### `annotations`

| Тип фигуры | `bbox` | `segmentation` | `area` |
|---|---|---|---|
| `rectangle` | `[left, top, width, height]` | `[]` (пусто) | `width * height` |
| `polygon` | описанный прямоугольник (min/max по точкам) | `[[x1, y1, x2, y2, ...]]` | площадь по формуле шнуровки Гаусса |

- `iscrowd` всегда `0` (инструмента для пометки «толпы» в UI пока нет).
- Полигоны не объединяются в один объект: каждый отдельный полигон — отдельная запись
  `annotations` (кнопки merge в UI нет).

---

## Почему координаты не в пикселях

**Стандартный COCO использует абсолютные пиксельные координаты.** У нас координаты
**нормализованы в диапазон `[0, 1]`** относительно натурального размера изображения.

Причина в том, как устроена разметка на фронтенде:

- Библиотека Annotorious внутри работает в пикселях.
- Наш сериализатор (`frontend/src/utils/annotationSerializer.ts`) перед отправкой на бэкенд
  делит все координаты на натуральные ширину/высоту изображения. Так координаты становятся
  независимыми от разрешения, а бэкенду **не нужно хранить размеры изображений**.

Как следствие в выгрузке:

- в `images` проставляется `width = height = 1` (координаты и так относительные);
- значения `bbox`, `area`, `segmentation` — дробные числа в `[0, 1]`, а не пиксели.

Перевод в пиксели потребовал бы хранить натуральные размеры каждого изображения — это задел
на будущее. Пока формат осознанно завязан на относительные координаты.
